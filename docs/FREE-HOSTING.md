# RecurTrace: free hosting, step by step

This guide creates one free Render web service and connects an existing free FalkorDB instance. No paid sandbox, persistent disk, SQL database, or custom domain is needed. Python checks execute on the visitor's device.

## 1. Create a GitHub account and repository

1. Visit https://github.com/signup and create a free account. Verify your email.
2. Sign in, select **+ → New repository**, and name it `recurtrace`.
3. Choose Public for a hackathon submission if the event requires source access. Do not add a template that overwrites the project's README.
4. The simplest Windows upload path is GitHub Desktop: install from https://desktop.github.com/, sign in, choose **File → Add local repository**, select `D:\Projects\AI driven\RecurTrace`, and choose to create a repository there if prompted.
5. Review the file list before committing. `.env`, `.venv`, `work`, and logs must not be included. The supplied `.gitignore` excludes them.
6. Commit the app and publish the repository. If you already created a GitHub repository, use it as the remote instead of creating a second one.

Alternative: use GitHub's **Add file → Upload files** to upload the source folders and files. Do not upload `.venv`, `.env`, `work`, or cache folders. Preserve the `app`, `static`, `tests`, and `docs` directory structure.

## 2. Create FalkorDB Cloud access

1. Open https://app.falkordb.cloud/ and create an account.
2. Choose only an instance explicitly labeled **Free**. If the account only offers a paid plan or a time-limited offer with automatic billing, stop; do not enter payment details to continue this guide.
3. Copy the instance's host, port, username, password, and TLS setting into your private notes or directly into Render's environment settings. Never put these in the repository or screenshots.
4. Confirm the plan's quotas and connection requirements. The public pricing page advertises a free plan without TLS, continuous persistence, or automated backups. Actual dashboard availability must be checked when provisioning.
5. Use synthetic examples only for a free demo that lacks encrypted database transport. This prototype is not intended for sensitive company incident reports on that configuration.

If the free instance is unavailable, the complete local Docker demo remains usable. Do not substitute a simulated graph or silently purchase a paid tier.

## 3. Create Render hosting

1. Open https://dashboard.render.com/ and sign up using your GitHub account.
2. Select **New → Blueprint** and connect the `recurtrace` repository.
3. Render should detect `render.yaml`. Review the service before applying: the plan must be **Free**, and there must be no paid additional services.
4. Enter the database environment variables requested by the Blueprint:

| Variable | Value |
|---|---|
| `FALKORDB_HOST` | Host from FalkorDB Cloud; no `redis://` prefix |
| `FALKORDB_PORT` | Port from the instance |
| `FALKORDB_USERNAME` | Username supplied by the instance; usually `default` when password authentication uses the default ACL user |
| `FALKORDB_PASSWORD` | The instance password |
| `FALKORDB_SSL` | `true` if the endpoint supports TLS, otherwise the documented setting for that instance |
| `FALKORDB_GRAPH` | `recurtrace` |
| `PUBLIC_DEMO` | `true` |
| `ENABLE_AI` | `false` |
| `SESSION_SECRET` | Automatically generated by the Blueprint; keep it stable across deploys |

5. Apply the Blueprint and wait for the deployment to finish.
6. Open its HTTPS `onrender.com` URL. No custom domain is necessary.

Manual web service setup, if needed:

- Runtime: Python
- Plan: Free
- Build command: `pip install -r requirements.txt`
- Start command: `uvicorn app.main:app --host 0.0.0.0 --port $PORT --proxy-headers --forwarded-allow-ips '*'`
- Add the environment variables above, including a random secret of at least 32 characters.

## 4. Check the hosted app

1. In **Setup & connections**, confirm FalkorDB is connected.
2. Click **Try the working demo**, then **Trace this change**.
3. Click **Compare with corrected example**. Expect original PASS, proposed regression FAIL, corrected PASS. Existing checks pass for all three.
4. Test the other two examples.
5. Open an incognito window. It should start with its own incident workspace.
6. Export a test and analysis report. Confirm the downloaded files contain the expected evidence.

The health endpoint reports backend availability separately from graph state. A Render deployment marked live is not proof that FalkorDB is connected; check both.

## Free-tier limitations

- Render free web services sleep after 15 minutes without incoming traffic. The first request may be slow. Do not use artificial keepalive traffic as a workaround.
- Local files on the web service are ephemeral. History is stored in each visitor's browser; graph facts are in FalkorDB.
- Browser workspaces use signed cookies, not accounts. Clearing cookies loses access to that workspace. This prototype has no account recovery or team sharing.
- Free database capacity is finite. Each workspace is capped at 50 incidents; this is a small demonstration, not an unlimited public service.
- Pyodide's initial download needs internet access and may be large on mobile connections.
- AI providers are separate from hosting. Leave AI disabled unless you have verified genuinely free access. The core demo does not need it.
